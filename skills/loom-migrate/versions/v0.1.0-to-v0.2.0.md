# hrx-loom v0.1.0 -> v0.2.0 (tested on v0.2.0rc1)

Release: ROCm/hrx-system `v0.2.0rc1` (release PR 2714, merge `bb876445`); the release-notes draft's "Behavioral changes and migrations"
table is the upstream contract. Compared: hrx-system `v0.1.0..v0.2.0rc1` (3001 commits), hrx-loom-library `dd23d2f5..v0.2.0rc1`, and the
wheels (rc1 sha256 `869ba98dea2fef8355aa190f962241cf62b067b7f5788b5d59b55cebd30658cd`). Written 2026-11-16 in campaign sdk020; the
procedure is in [../SKILL.md](../SKILL.md). The release candidate is **not on PyPI**: install the wheel from the GitHub release.

## 1. Summary

Measured on the 51-package fleet (programs-only build of the v0.1.0 kit, `sweep.py --sdk` the rc1 venv): 50 packages fail to parse
(71 program files; the 51st, Flash-Next, was already built against a dev SDK that spells the new syntax), and once those two renames
are fixed the whole fleet parses (0 of 448 files fail) and 50 of 51 link. Everything else below is found at load time.

| Severity | Change | Fleet impact |
|---|---|---|
| HARD (parse) | `vector.constant` removed: `vector.splati` (int, predicate, index) / `vector.splatf` (float) | 71 files, 50 packages |
| HARD (parse) | `command.program.{def,decl,launch}` -> `command.{def,decl,launch}` | same files |
| HARD (load) | card `presets.*.execution.pool_capacity` rejected (`unknown model field`) | 50 of 51 cards |
| HARD (load) | `publish_epoch` gains a leading `control_state: buffer` argument (13 args) | 51 of 51 |
| HARD (load) | image component finite ABI: `prepare_batch(state, tags, batch)`, `run(state, ..., batch)`, new `collect_batch` | 22 packages with an image encoder |
| HARD (deployment) | elastic shared KV pool: the server derives the pool from `--memory_bytes` (or the device's capacity); kit kernels bound `llm.pool` to 16..1048576 | 16 of 50 at 32 GiB, 36 of 50 with no `--memory_bytes` exceed the bound |
| INSTALL | rc is a GitHub release asset (sha256 from `SHA256SUMS`), catalog association is the tag `v0.2.0rc1` | installer, pin, card Quick start, CI |
| SILENT | active-wait default 100 us -> renewing up to 1 s; `legacy-amdgpu` and ROCr removed (loom-test and loom-benchmark now on the same HAL as loom-serve) | kernel A/B numbers from v0.1 are not comparable |
| SILENT | request semantics: unknown fields ignored (were 400), nulls = defaults, `max_completion_tokens` wins, `tool_choice` no longer gates tool calls | gates that send `stop`/`tool_choice` |
| N/A | image RGBA8 output, sequence `prepare_request`, C++ attribute/view renames, LoomC API, HAL VM APIs, importers, `weight_activity` | no such services or C++ in the repo |

## 2. Breaking changes

### 2.1 `vector.constant` -> `vector.splati` / `vector.splatf` (upstream #2464)
- **Class**: source IR, HARD parse (`error [PARSE/006]: unknown op 'vector.constant'`, then `PARSE/001 undefined SSA value`).
- **Before / after**: `%z = vector.constant 0.0 : vector<8xf32>` -> `%z = vector.splatf 0.0 : vector<8xf32>`;
  `%m = vector.constant 252645135 : vector<4xi32>` -> `%m = vector.splati ...`. The op is chosen by the **element type**: f16, f32, f64,
  bf16, f8* -> `splatf`; i8, i32, i1 (predicate), index, offset -> `splati`. There is no compatibility spelling. Operand-driven
  `vector.splat` and the dense-list `vector.constanti [..] : vector<16xi8>` are unchanged: never rewrite `vector.constanti`.
- **Touches**: every emitter and checked-in `.loom`/`.patch` with the op: `starter/gen_llm.py`, `gen_gemm.py`, `gen_moe.py`, `quant_values.loom`,
  `draft/*`, `gen_flash2*.py`, `gen_gdn_chunk.py`, `vision/gen_vision.py`, the reference examples under `loom-port-llm/reference/` and
  `loom-optimize/reference/`. In the fleet: i32 about 7.5k, f32 5.3k, i8 2.4k, f16 0.8k sites.
- **Step**: `rewrite_v010_v020.py PATH` (packages and `.loom`/`.loom-test`/`.patch` files); `--py` for generator sources, where it rewrites
  only sites whose element type is literal and reports the rest (`vector<{n}x{ty}>`, a placeholder type) as `manual`: choose by hand.
- **Verify**: `sweep.py --sdk NEWVENV` shows no `PARSE/006`.

### 2.2 `command.program.{def,decl,launch}` -> `command.{def,decl,launch}` (upstream #2476)
- **Class**: source IR, HARD parse. Serialized operation ordinals are unchanged (bytecode compatible), only the text changed.
- **Touches**: emitters `starter/build.py`, `gen_llm.py`, `dual_target.py`, `f16o_fuse.py`, `draft/*`, `vision/gen_component.py`; fleet tools that
  parse programs (`fleet/diff_fleet.py`, `loomtext.py`, `stage_equiv.py`) must accept **both** spellings so base(v0.1) vs head(v0.2) diffs work.
- **Step**: `rewrite_v010_v020.py` (same pass as 2.1). **Verify**: sweep.

### 2.3 `publish_epoch` takes the retained control state first (upstream #3125)
- **Class**: program ABI, HARD at model load (export signature mismatch).
- **Before / after**: `@publish_epoch(%plan: buffer, %media_plan: buffer, ...)` (12 args) ->
  `@publish_epoch(%control_state: buffer, %plan: buffer, ...)` (13 args, 0 results). `control_state` is the same borrowed buffer passed to
  `epoch`/`encode_epoch`/`encode_state`. The body may ignore it. The call from the wrappers is
  `func.call @publish_epoch(%control_state, %plan, ...) : (buffer, buffer, ...) -> ()`.
- **Touches**: `starter/templates/control.loom` (def), `templates/service.loom` (decl and the `text_`/`sequence_` `publish_epoch_v1` wrappers),
  `draft/build_draft.py` (`plain_publish_epoch` rename and wrapper), `reference/qwen4exp-example/catalog/program/text_epoch.loom`.
- **Step**: `rewrite_v010_v020.py` rewrites def, decl and call sites (any `@publish_epoch`, `@*_publish_epoch`, `@*_publish_epoch_v1` whose first
  parameter is `%plan`; already-migrated text is skipped). `--no-publish-epoch` turns it off. For a generator, change the template once.
- **Verify**: GPU smoke (serve + one chat). The sweep cannot see it (link passes either way); a signature mismatch is a load error.

### 2.4 Image component finite batch ABI (upstream #2838, #2906)
- **Class**: program ABI, HARD at load for packages with an image encoder (22 in the fleet).
- **Before / after**: `text_image_prepare_batch_v1(state, tags, ranges, packed) -> (i32, buffer, buffer)` and
  `text_image_run_v1(stage, input: hal.buffer, output: hal.buffer)` ->
  `text_image_prepare_batch_v1(state, tags, batch: ptr<finite.batch>) -> (i32, buffer, buffer)` (call `finite.batch_pack(batch)` for
  `%ranges,%packed`), `text_image_run_v1(state, stage, input, output, batch)`, and a **new required export**
  `text_image_collect_batch_v1(state, batch)` that calls `finite.batch_finish(batch)`. Declare
  `type.decl import("finite","batch") @FiniteBatch` and `func.decl import("finite","batch_pack")` / `("finite","batch_finish")`. Our encoder is one-shot, so
  `batch_finish` in collect mirrors the upstream fixture; without it the server's "terminal offers agree with published rows" check fails.
- **Touches**: `starter/vision/gen_component.py` and the Flash-Next package. Reference: the in-tree fixture `serve/fixture/projector/{service,control}.loom` at the new tag.
- **Step**: hand edit in the generator (not scripted: `rewrite_v010_v020.py` only reports the old signature as `manual`).
- **Verify**: GPU smoke with one image.

### 2.5 Card: `pool_capacity` removed; elastic KV pool (upstream #2583, #3137)
- **Class**: card schema (HARD load: `unknown model field 'pool_capacity'`) and deployment.
- **Before / after**: `presets.*.execution.pool_capacity` combined logical addressability and a per-model cache quota. Now `context_capacity` limits one
  conversation, shared physical capacity supplies the elastic ceiling, and the optional `--memory_bytes` flag (not a card key) tightens the pool-wide
  budget. The server hands the program `pool = memory_bytes / page_bytes * block` (no weights deducted). With `--pool_backing=fixed` (R9700 path)
  `pool = context_capacity`. `context_capacity` must stay a multiple of the 16-position page.
- **Touches**: writer `starter/build.py`; readers `loom-fleet/scripts/eval.sh`, `loom-benchmark/scripts/card/{card_lib,make_info}.py`, `loom-kb/choices.py`,
  scope.json files, card test fixtures, `fleet/manifest.json` `build.pool`, `fleet/regen.py`, error texts that match "increase pool_capacity" (reworded upstream).
- **Step**: `rewrite_v010_v020.py` removes the key from `model.json` (formatting kept); writers stop emitting it; readers tolerate its absence.
  **Kernel bound**: kit kernels declare `config.decl @llm.pool : range(16, 1048576)` (and `index.assume` of the same range, and page-offset assumptions).
  A pool above 1048576 positions violates it at stage specialization. Either widen it (upstream uses `range(0, 2147483584) multiple_of(64)`) after
  proving the 32-bit offset arithmetic with a kernel A/B at a pool above 2^20, or cap the pool per model through `--memory_bytes`.
- **Verify**: `sweep.py` link with the card config; GPU smoke with and without `--memory_bytes`.

### 2.6 Install, pin and catalog
- **Class**: install and pin. **Before**: `pip install hrx-loom==0.1.0` (PyPI); a pin-less `llm_config.json "sdk"` meant 0.1.0; CI-artifact pins expired in about 90 days.
  **After**: the rc wheel is a GitHub release asset; install it by URL with its sha256 (`pipx install "hrx-loom[hf] @ URL#sha256=..."`), verify against
  the release's `SHA256SUMS`; pin `{"hrx_loom": "0.2.0rc1", "source": "release", "wheel_sha256": "...", "hrx_system_sha": "..."}`; the catalog association is the tag
  `v0.2.0rc1` (`git fetch origin tag v0.2.0rc1` or check out `FETCH_HEAD`; a plain `fetch origin <tag>` leaves only `FETCH_HEAD`). A package with no pin means 0.1.0
  explicitly, so old published cards keep working on 0.1.0. A release pin never expires.
- **Touches**: `loom-setup/scripts/{install_loom.sh,ensure_sdk.sh,sdk_pin.py}`, `render_card.py` Quick start, `info_schema.json` SDK enum, `.github/scripts/*` (they install
  through `ensure_sdk.sh`), version strings in `loom/SKILL.md`, `loom-setup/SKILL.md`, `loom-port-llm/SKILL.md`, `loom-roofline/SKILL.md`, `loom-kb/topic/*`, `docs/`.
- **Step**: hand edit. **Verify**: install twice (second run on the existing clone); `ensure_sdk.sh` picks 0.1.0 for a pin-less package and the new one for a release pin.

### 2.7 Device runtime and tools
- libamdf HAL replaces ROCr for `amdgpu`; `legacy-amdgpu` is gone, so `loom-test` and `loom-benchmark` run on the same HAL as `loom-serve`: **kernel
  timings and pass/fail from v0.1 are not comparable**; re-baseline in the same job.
- Active-wait default: 100 us -> renewing up to 1 s. Keep the explicit `amdgpu://?completion_spin_ns=4294967295` (still a valid uint32) in serve.sh and cards:
  a short window parked long prefill epochs (Laguna 32k: 1187 vs 1539 tok/s). `LOOM_ACTIVE_WAIT=0` (parked baseline) becomes `--wait_mode=blocking`
  (new flag). Whether the explicit URI is redundant now is a measured question, not an assumption.
- CLI: `loom-serve --model=DIR` accepts a directory; `loom-fetch` takes `huggingface:ORG/REPO[:PRESET][@REV]`, repo URLs and `--model ID` over the SDK's catalog,
  `--output` is optional (default `./MODEL_ID`); `loom-link` lost `--input-options` (C++ import moved to `loom-import-cxx`); `amdf-info --format=json` is new.
  No flag the repo passes was removed or renamed.

## 3. Mechanical steps

For a package or tree you own (the hand-edit items are 2.4 and the pool bound of 2.5):

    export LOOM_SKILL_DIR=...   # this skill's directory
    python3 "${LOOM_SKILL_DIR}/scripts/rewrite_v010_v020.py" --check PKG_OR_TREE        # what would change; exit 1 if anything
    python3 "${LOOM_SKILL_DIR}/scripts/rewrite_v010_v020.py" PKG_OR_TREE --json rewrite.json   # apply (add --py for generator sources)
    python3 "${LOOM_SKILL_DIR}/scripts/sweep.py" --sdk NEW_VENV PKG_OR_TREE --json sweep.json  # parse + link under the new SDK
    # then: the image component (2.4), the pin and install (2.6), serve on the new SDK and chat once

For the fleet (campaign order): fix the emitters to match the rewrite's output on a copy of the old fleet; rebuild programs only; sweep; explained diff;
DevLab smoke; SDK A/B; publish to staging (procedure steps 3 to 6 in [../SKILL.md](../SKILL.md)).

## 5. Verification
- Control: the v0.1.0 venv on the v0.1 fleet: 50 packages parse and link; Flash-Next does not parse (it is written in the new syntax: `unknown op 'vector.splati'`).
  The rc venv on the unmigrated v0.1 fleet: 50 parse failures, the first-error class `PARSE/006 unknown op 'X'`. After the rewrite on a copy of the fleet:
  0 parse failures, 51 packages parse; 50 link (the Flash-Next failure, `SYMBOL/013` on `@qwen38.packet_capacity`, is its own library-derived package: refresh it from
  the library tag instead of rewriting it).
- Program diff of old fleet vs new fleet is non-empty by design: classes are the two renames (every `llm.loom`, `vision_encoder.loom`), the `publish_epoch` lines,
  the vision ABI lines, the card `pool_capacity` removal and the pin. Show the remainder after mapping the renames back is only those.
- GPU smoke (DevLab): dense small, hybrid recurrent, vision, and one R9700 job; serve, a chat, a tool call (and an image). Then the SDK A/B per model and device.

## 6. Behaviour changes to measure
- Decode: launch work (one-packet AQL, scalar PM4 copies, warm recordings) should help small, launch-bound models and be neutral on large ones.
- Prefill and TTFT: mixed prefill/decode scheduling was rewritten (`packing.c`, `epoch.c`), so 4-stream and TTFT can move either way.
- Completion policy: the default active wait is now 1 s renewing; our explicit URI overrides it. Compare default vs explicit (ledger item).
- Requests: `stop`, `n`, `logprobs`, `frequency_penalty`, `parallel_tool_calls`, `user` were HTTP 400 and are now ignored; there is no stop-sequence handling in the native
  text service in either version (only EOS and `max_tokens`). `tool_choice=none` no longer suppresses tool calls (the server parses tool text whenever `tools` is non-empty).
  Wrongly typed `temperature/top_p/top_k/seed` are skipped, not 400. `max_completion_tokens` wins over `max_tokens`; the cap is INT32_MAX (was 16384).
  Kit `request_options` reads only number-typed sampling fields; `chat_template_kwargs`/`enable_thinking` are read by the kit's `chat_begin`, not natively.

## 7. Simplifications available
`loom-fetch huggingface:ORG/REPO:PRESET` (revision pinned by the tool) and `loom-serve --model=DIR` in card Quick starts; catalog models by `loom-fetch --model ID --preset P`
(the SDK's own catalog revision, no raw GitHub `main` URLs); no `pool_capacity` computation anywhere (one `--memory_bytes` budget); release pins that never expire;
integrations need not strip extension fields or nulls; `amdf-info --format=json` for device probing. Status of each is tracked in the campaign's simplification ledger.

## 8. Opportunities
PLE-from-disk (Flash-Next): the upstream parameter gather and `io/` code is byte-identical between the dev pin and rc1, so there is no PLE-specific gain; only generic
queue/completion work could trim read latency (estimated 0 to 3 % on a 2k prefill, unmeasured). File an issue only if the A/B shows a gain. Other opportunities are
listed in the campaign's `notes/opportunities.md`.

## 9. Gotchas
- `unknown op 'vector.constant'` then a cascade of `undefined SSA value` -> the op was split by element type -> `rewrite_v010_v020.py`; fix the first error and the cascade goes.
- A rewrite that touches `vector.constanti` breaks the dense-list op -> it is unchanged in v0.2 -> the regex requires whitespace after `constant`.
- `unknown model field 'pool_capacity'` at serve, `KeyError: 'pool_capacity'` in eval/card scripts -> the card schema dropped it -> remove from writers, tolerate absence in readers.
- A package serves on 0.1.0 but fails at load on the new SDK with a `publish_epoch` signature error -> the leading `control_state` argument -> rewrite (2.3).
- `fleet/link_check.py` truncated `@qwen38.packet_capacity` to `@qwen38` and reported `SYMBOL/017 root symbol has no definition` -> its root regex used `\w+` -> match `[\w.]+` (sweep.py does).
- `SYMBOL/013 ... incompatible contract field 'symbol interfaces'` on Flash-Next after the renames -> its checked-in programs are library-derived (dev SDK pin) and their config contract does not link under rc1 -> refresh them from the library tag instead of rewriting.
- `git fetch origin v0.2.0rc1` then `git checkout v0.2.0rc1` fails in an existing catalog clone -> a plain fetch of a tag leaves only `FETCH_HEAD` -> `git fetch origin tag v0.2.0rc1` or check out `FETCH_HEAD`.
- `pip install hrx-loom==0.2.0rc1` finds nothing -> the rc is not on PyPI -> install the release wheel by URL with its sha256.
- `loom-opt --version` is not a flag -> read the version with `python -c "import importlib.metadata as m; print(m.version('hrx-loom'))"` in the venv (`loom-serve --version` exists in v0.2).
- Kernel A/B timings differ from last month's -> `loom-test` moved off `legacy-amdgpu` to the libamdf HAL -> re-baseline both sides in one job.
- Gotchas found by the other engineers during the sdk020 campaign are added here before the entry is final.

## 10. Not applicable

Python importer frontends, image RGBA8 output, sequence `prepare_request` (all 51 services are `text`), the telemetry event `weight_activity` -> `parameter_activity` (no consumer
in the repo), and the build options `IREE_HAL_DRIVER_AMDGPU` -> `IREE_HAL_DRIVER_AMD_GPU` (we install wheels). The K/V interleave in attention (library #87) is an authoring
opportunity, not a migration item. If one of these appears in your own code, the release notes' migration table has the exact rename.
